# 外部小米流适配：本地部署边界

本项目不分发厂商私有桥接、账号会话、native library 或运行树。准确上游与许可证须先独立审查；参考 [集成边界](../integrations/xiaomi-stream-gateway.md)。

## 配置原则

- 厂商认证在独立的 Git 外运行环境处理，凭据不放在源码、命令行参数、日志或示例里。
- 对核心只提供匿名逻辑 camera ID 与无凭据、无查询参数的 loopback RTSP。
- 物理设备、视频通道和房间分开登记，不根据设备名称猜房间。
- 每路保留独立接流健康与解码代次。一路故障不应造成其他路重启或身份继承。
- 原生与辅助视图不是两个人，也不能将框数当人数。
- 默认不启用音频、厂商事件、云端复核、自动发现上传或开机自启。

## 接入顺序

1. 审查外部桥接的准确来源、许可和所需网络访问。
2. 在私有环境完成明确授权的认证，不向助手或公开 Issue 提供凭据。
3. 使用匿名通道配置，把媒体只发布到 IP loopback。
4. 先对一条流进行有界解码与断流恢复检查。
5. 使用核心媒体/缓冲适配器检查实际时间轴与证据覆盖，再扩展路数。
6. 运行状态、样本、标注与诊断输出保存在 Git 外；公开只提交通用代码和合成测试。

不提供与某一家庭绑定的默认安装路径、设备别名、端口映射、房间清单或操作日志。外部桥接命令以其已审查的版本文档为准，不能假称核心包含该实现。

## 网络与停止行为

默认仅回环发布；不自动改变 WSL 网络模式、Windows 防火墙或路由器。任何 LAN 访问必须由用户另行授权并限制来源，公网暴露不属于常规开发。

停止和启动均由使用者明确执行；健康检查、恢复开发会话或生成模板不得自动恢复已停止的桥接与分析服务。

## 验收

分别检查来源健康、连续接流、解码缺口、候选/分析吞吐、资源峰值和恢复行为。接流正常不代表宝宝检测、角色绑定或看护判断准确。

核心运行模板见 [Ubuntu/WSL 手动部署](home-wsl-runtime.md)。
